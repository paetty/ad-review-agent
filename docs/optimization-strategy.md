# 本轮修复与后续优化策略

更新：2026-10-23。目标：先修复真实小样本暴露的业务决策错误，再验证模型收益，不先扩框架或检索算法。

最新进度：五条真实复测已完成，本轮四项同时匹配5/5，另一次同版本为4/5，均保留；新Schema真实兼容性已通过本轮验证。详见[最新真实复测报告](model-pilot-retest-2026-10-23.md)，不要把它与历史离线回放混用。

## 一句话总结

系统现在区分三种结果：有具体问题线索；没有足够信息、暂不分类；未发现明确问题。免责声明单独展示，无依据的模型候选单独保留，不计入问题统计。高风险、低置信度具体问题和证据不足仍按策略转人工。

## 为什么这么改

修复前的真实模型五条测试已经记录在[原始验证报告](model-pilot-verification.md)。问题不是接口没通，而是语义与业务决策混在一起：

- 模型对两条正常反馈判断正确，程序却把“尚未完成合规审核”的通用提醒当作缺失信息，错误转人工。
- “感觉怪怪的”没有具体故障或素材线索，模型却猜测“素材不清晰”，程序仍把候选作为已发现问题。
- 风险护栏必须保留：原模型对返回困难输出高风险却不要求复核，原程序兜底是有效的。

## 修改后的具体行为

### 正常反馈

“没有自动跳转，关闭按钮也正常” → no_issue + no_explicit_issue → 不因通用免责声明强制复核。它不表示整张广告已通过审核。

### 模糊反馈

“感觉怪怪的，但我说不上来哪里不对” → 不能仅凭这句话确定画面模糊。旧模型猜出的unclear_material保留为未采纳候选，最终为no_issue占位 + insufficient_evidence + 人工补充信息，不计入素材不清晰的统计。

### 低置信度但有具体线索

“按了好多下返回，才回到天气页” → 即使模型置信度较低，也保留返回困难线索并转人工。没有采用“低于某个置信度就把问题删掉”的一刀切方法。

### 正例与不确定性同时存在

“感觉怪怪的，但我按了六次返回键才退出”不是纯感受，不会因为开头有“怪怪的”就清除具体问题。确定性高风险正例仍保留，模型不能把它降成正常。

## 仍然存在的限制

1. 纯感受识别是一个明确、有限的短语规则，不是通用语义理解。模型状态字段和提示词可补充表达能力；本轮五条真实复测已验证，但未覆盖更多新表达。
2. 引用存在、逐字匹配只证明可追溯，不保证语义支持。当前支持检查是整条反馈级别，不是逐标签的因果或蕴含验证，混合多问题仍可能出现部分标签缺少依据。
3. 数值策略边界已加到提示词，但尚无完整的建议阈值审查器；旧响应中的“返回步骤数<=1”不会因离线回放自动变成可靠标准。正式报告仍需业务确认。
4. no_issue + insufficient_evidence暂时沿用原分类接口的占位方式，不能解释为正常。低风险只表示没有采纳具体风险类别，不表示安全核验通过。
5. 新Schema要求外部模型输出assessment_status；历史回放本身不能证明接口兼容，但后续真实复测已确认本次千问服务可以返回并解析该字段。换服务或模型仍需单独验证。

## 后续优化顺序

### 下一轮：验证真实模型，而不是继续加功能

同五条的真实复测已完成，最近两次结果为4/5和5/5；接口契约通过，但额外复核存在波动。下一步固定配置扩大剩余开发样本对照，记录每条失败，不反复调同五条追求全对。扩大真实调用会消耗额度，尚未执行。

8条validation当前全是no_issue参考，适合检查正常/否定误报和误转人工，不能据此评估问题类或高风险召回。12条holdout_candidate虽未执行，但作者和使用者看过内容，不能改名为独立盲测。

### 再下一轮：补足评测覆盖

补充独立编写与人工确认的新样本，覆盖多标签、隐晦高风险、正常/否定、模糊与具体问题混合、无相关知识及不同平台。按表达家族拆分开发与测试；最好由另一位标注者独立判断，无法做到就如实称单人复核。不得把未核查真实广告的纯文本标签当作素材事实。

优先检查：分类完全匹配、具体问题类F1、高风险召回及样本数、无证据具体标签率、正常样本误转人工率、引用支持度与建议可执行性。证据不足识别应单独统计，不能混进正常准确率。新的错误类型应先写反例测试，再改代码。

### 最后：按失败归因决定技术升级

知识没召回时再对比TF-IDF、Embedding与重排序的Recall@4/MRR；知识已召回但模型硬猜时应优先改输出契约、证据约束和判断逻辑。当前故障证据不足以证明更换检索算法能解决问题，因此本轮不更换。

只有需要核查图片可见事实时再接视觉/OCR；视频时序、跳转链路和频次分别需要视频、操作与曝光日志证据。保留现有有边界的LangGraph工作流，不为“更像Agent”增加自动处罚或修改投放的权限。

效率和成本后续记录真实端到端P50/P95（包含检索与路由）、输入/输出Token、实际费用与人工修改量。不能把离线回放耗时、Demo模拟计量或模型置信度当作线上效果。

## 面试可以怎样解释这次迭代

我先用少量真实模型调用做失败分析，发现模型语义判断和系统业务路由是两类问题。随后把状态、免责声明和候选推断分开，增加证据校验与人工兜底，并用固定历史响应回放验证程序修复。已知缺陷回归通过，但我不会把它当作泛化准确率；下一步再用固定配置和独立样本验证真实模型收益。
