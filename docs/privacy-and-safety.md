# 隐私、安全与 Threat Model

原则：数据最小化、后端密钥、默认不记录完整原文、高风险人工复核、合成内容显式标识、可删除。系统不采集 IMEI、姓名、手机号、身份证，不自动执行处罚或投放。

- API Key 只从后端 env 读取；前端只有 API 地址。
- CSV 限类型、2MB、UTF-8、字段白名单；正文检测手机号、身份证、IMEI、邮箱，命中以 `policy_guardrail_triggered` 阻止。
- 普通日志不打印请求/响应正文或密钥；当前无原文应用日志。
- critical 强制人工复核；恶意/诈骗/病毒/隐私只给暂停自动放量建议，系统不执行。
- DELETE API 可删除分析；人工修正版单独保存。

| 威胁 | 影响 | 缓解 |
|---|---|---|
| 密钥进入前端/日志 | Provider 滥用 | 后端 env；静态测试禁止前端密钥名 |
| PII 混入 | 隐私违规 | 字段与正文双重检测 |
| Prompt injection | 伪造结论/引用 | schema、引用白名单、规则后处理 |
| 恶意大 CSV | 资源耗尽 | 类型与 2MB 限制、逐行隔离 |
| 越权自动处罚 | 业务损失 | API 无处罚能力，必须人工复核 |
| 人工编辑破坏追溯 | 原始证据丢失 | 原输出不可变，修正版新记录 |

局限：正则可能误报/漏报；SQLite 不适合多租户生产。生产化需认证、RBAC、审计、加密、保留期限、限流和专业合规评审。
