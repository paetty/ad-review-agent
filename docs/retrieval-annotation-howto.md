# 怎样标注独立检索查询

## 先区分两种任务

反馈标注：这句话属于哪类问题、风险多高、证据是否充分。

检索标注：面对这句话，哪些知识片段能支持后续核查或建议。它不是让标注者决定系统应该排第几。

## 最小执行步骤

1. 请实际使用者先写10—20条自然提问或反馈，不看现有8条开发查询，也不要从规则标题复制关键词。尽量包括同义改写、含糊表达、否定、多个问题及平台差异。
2. 记录query_id、query、platform和场景。先不运行检索，也不看模型答案。
3. 人工阅读完整候选资料，为每个查询标记相关chunk_id，并写一句理由：直接支持=2，间接相关=1，不适用/无关=0。可以有多个直接支持片段，也可以没有支持片段。平台专属条款不适用于别的平台；用户声称不是已核实事实。
4. 最好两人独立标注并讨论分歧。若只有本人确认，就如实记为单人开发评测。保留争议，不为了方便强行选一个答案。
5. 保存人工答案后再运行TF-IDF/BM25，检查Top-4中是否包含直接支持片段，并查看漏检；没有适用片段的查询单独看错误引用率，不强行纳入召回分母。
6. 用同一份冻结的查询与答案对比Embedding/重排序，观察Recall@4、MRR、无关引用和最终建议质量。只有提升能覆盖额外耗时与成本时才考虑升级。

## 教学示例（不是独立盲测题）

查询：“手指碰到叉号却进了商店，我是想关掉。”

平台：generic。需要先核查真实操作。可参考第十一条误导点击摘要；如确认属于弹出/开屏广告，还可能参考第十条关闭要求。不能因检索到条款就认定违反条款。

查询：“老是刷到这张脸，是不是广告放得太勤？”

素材轮换和频控调查都可能相关；还缺少同素材曝光记录，不能给出已经超标的结论。

## 当前已有工具的限制

scripts/compare_retrieval.py里的8条查询由开发者根据规范编写，只是开发探针。它目前没有导入人工相关性标注集，也没有执行Embedding对照。不能把其高分称作独立检索验证。

建立好独立查询后，再增加从已确认标注文件读取评测的入口；原有48条反馈候选不等于这份检索标注集。
